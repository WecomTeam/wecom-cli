# 局部替换在线文档内容

当前 CLI 没有单独的段落替换命令。局部替换必须复用 `contents get` 与 `contents overwrite`，按“读取完整正文 → 唯一定位旧片段 → 本地生成完整新正文 → 写前复核 → 全文覆盖 → 写后完整回读”的顺序执行。任何一步无法确认时停止，禁止退化成前插、追加或盲目覆盖。

## 适用范围

- 覆盖当前段落、替换某一段文字；
- 修改唯一标题下的一段或一个连续章节；
- 删除文档中的一个唯一连续片段；
- 保留目标片段之外的全部内容。

用户要求覆盖整篇文档时改用 `doc contents overwrite`；用户没有明确替换语义时改用 `doc contents append`。

## 标准流程

### 1. 读取完整正文

```bash
wecom-cli doc contents get --json '{"docid":"<docid>","content_type":"markdown"}'
```

- 短内容读取返回的 `content`；长内容使用返回的 `file_path`，通过 Read 工具读取完整文件。
- 将完整 Markdown 原样保存为工作区内的 `before.md`。不得只保存页面摘要、截断内容或模型复述文本。
- 如果读取结果无法完整表达文档中的图片、表格或其他结构，停止并说明当前 CLI 无法安全完成局部替换，不得用纯文本覆盖富文本文档。

### 2. 唯一定位替换范围

- 把要替换的当前原文原样保存为 `old.md`，把替换后的新内容保存为 `new.md`。
- 旧片段必须是 `before.md` 中连续且唯一的原文。用户只给标题或描述时，先从读回正文中确定完整旧片段；目标不存在或出现多次时，先让用户消歧，写入前停止。
- 新内容可以为空，表示删除该唯一片段；旧内容不得为空。

### 3. 生成完整新正文

使用技能目录内的脚本做唯一替换：

```bash
python3 <wecomcli-doc技能目录>/scripts/replace_text.py \
  --input before.md \
  --old old.md \
  --new new.md \
  --output after.md
```

脚本仅在旧片段恰好出现一次时生成 `after.md`；未找到或多次出现都会失败且不写输出文件。生成后确认脚本返回的 `prefix_sha256` 与 `suffix_sha256` 已记录，它们用于证明目标前后的正文未被本地替换过程改动。

### 4. 写入前再次读取并比对

再次执行 `doc contents get`，把最新完整 Markdown 与 `before.md` 逐字节比较：

- 完全一致：可以继续写入；
- 不一致：说明文档已被其他人或流程修改。废弃本次 `after.md`，从第 1 步重新读取和定位，禁止覆盖新变化。

### 5. 覆盖写入完整新正文

```bash
wecom-cli doc contents overwrite --json '{"docid":"<docid>","content_type":"markdown","file_path":"<after.md绝对路径>"}'
```

必须使用包含全部正文的 `after.md`，不能只传 `new.md`。写接口返回成功只代表请求完成，不能据此向用户宣称段落已替换。

### 6. 写后完整回读

再次执行 `doc contents get` 并验证：

1. 远端完整 Markdown 与 `after.md` 一致；
2. 新片段位于原目标位置且只出现预期次数；
3. 目标前后的内容分别与 `before.md` 的前缀、后缀一致；
4. 旧片段已被替换，没有形成“新内容在前、旧内容仍保留”的重复结构。

只有四项全部通过时才能说明局部替换成功。任一项失败时必须报告“写后校验失败”和具体差异，不得继续追加补写，也不得声称操作成功。

## 安全边界

- 当前 `contents overwrite` 没有向技能暴露可传入的文档版本号。写前二次读取可以发现已发生的并发修改，但无法消除二次读取与覆盖请求之间的竞态窗口。高并发编辑中的文档应停止操作，等待编辑稳定后重试。
- 不得使用估算字符索引、固定删除范围或标题名称猜测目标位置。
- 不得把多个匹配中的第一个当作目标；必须先消歧。
- 不得为了避开 Markdown 转义改用 Shell 拼接长文本；通过文件传入完整内容。

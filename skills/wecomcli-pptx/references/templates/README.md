# 范例池使用手册

wecom-pptx 的版式范例池：**扁平 9 套，没有分支**；每套 = 预设 `DESIGN.preset.md` + 外壳 `shell/content.jsx` + 3～4 页可编译范例 `slides/*.slide`。模板只管版式（外壳、分区、字号层级、图位、标志性处理），颜色是默认值，可以整体替换。生成流程里所有与范例池有关的规则都在本文件，create-from-scratch / human-alignment 只放接入点。

> 范例池整个在 `assets/templates/` 下：索引 `assets/templates/index.json`，9 套内容 `assets/templates/<slug>/`（预设、外壳、范例页）。要 `read` 某套的预设或范例时，**照抄 `index.json` 里 `preset` / `shell` / `slides` 字段给出的路径**（相对技能根目录，可直接用），不要自己拼目录。`build_page.py` 会自行定位模板池，命令里不需要给模板路径。

## 1. 套与标签

池子是扁平的，选套靠打分不靠分类（打分规则见 create-from-scratch Step4）。每套带四维标签：

| grove | 文献综述 | 中高 | 中 | 明暗交替 | 森绿与纸面交替，古典衬线 |
| signal | 经营分析 | 高 | 高 | 明暗交替 | 藏青与骨白逐页交替，古金强调 |

## 2. 预览卡（Step2）

每张卡 = 一种版式 + 一套配色；每张卡背后必须是池里一套真实的版式。**配色每次都按主题现场推导**（见 §3），预设里的色彩池只是兜底的默认值；各卡的配色必须一眼分得开（色相或明暗方案不同），不得全部同一色系。

- 3 张卡就是 Step4 在全池打分的前 3 套，按贴合度排 A～C，最贴合的标「推荐」。
- 命中政务闸门时只出 2 张卡（政务工作、表彰庆典）。
- 每张卡各配一套按 §3 生成的推导配色（各卡的 `--hue` 至少差 60°，至少一套冷色、一套暖色或中性色）。某张卡的色相命中 §3 的距离闸时，该卡就用那套的默认配色，照样满足「各卡一眼分得开」。深底只出现在默认就是深底的套上，不靠反色造。政务两套默认红金，用户点名才换。
- 用户点名了颜色、品牌色或「用默认」→ 按用户说的做成 A 卡并标「推荐」，其余各张仍与之拉开。
- 卡片顶部只写「A · 套名」，色板条取该卡实际配色，封面缩略图按该套 `slides/01_cover.slide` 骨架换上用户真实标题渲染。
- 预览卡默认必弹，但**拿不到回应一律按跳过继续生成，不许停下来等**（没点 / 审批超时 / 组件失败都算，见 human-alignment §1）；只有用户上传了自己的 PPT 模板（**不走本手册**，见 [../create-from-template.md](../create-from-template.md)），或在本次对话里明确说了「不用问 / 直接做」才主动跳过；文字提问被跳过或没有文字提问，都不算跳过预览卡的理由。跳过时：版式取 Step4 打分的第 1 名，分数并列就在并列的里 `python3 -c "import random; print(random.choice([...本分支 slug...]))"`；配色照样按 §3 推导，不退回默认；版式与配色的选择理由写进 STORY.md 第二行（只写文件，不对用户复述）。

## 3. 配色推导（每次生成都做）

**每份 PPT 都要做配色判定，合法结论有两个：换色，或判定主题色相与本套默认吻合、直接用默认配色。** 没有第三种——不许生成一个跟默认几乎一样的配色来充数（那会通过所有机检，看上去却还是这套的原色，等于换了个名义）。不要手写整张映射表——手写既慢又容易压掉对比度，用 `palette` 子命令算。

> **换色失败不影响用模板**：`palette` 跑不起来（命令被拒、没有 python、报错）时，直接用该套默认配色继续走 §4，并在交付时说明配色可再调；**绝不因为换色这一步不通就放弃模板、改成自由发挥的版式**。

1. 先从主题、行业、受众、场合推一句「色彩意图」（如「医疗 · 冷静可信」「文旅 · 温暖热烈」「政务 · 庄重红金」），写进 DESIGN.md，并据此定一个主色相：

   | 色相 | 0 红 | 30 橙 | 45 金 | 90 橄榄 | 140 绿 | 165 青绿 | 190 蓝绿 | 215 蓝 | 240 靛 | 265 紫 | 300 品红 | 330 玫红 |
   |---|---|---|---|---|---|---|---|---|---|---|---|---|

2. 生成映射表：

   ```bash
   python3 "{baseDir}/scripts/build_page.py" palette --set <slug> --hue <色相> [--sat 0.8] [--spread 0.6]
   ```

   - `{baseDir}` 表示当前 Skill 所在目录（`wecomcli-pptx`）。执行时必须替换为实际绝对路径。
   - 脚本已经存在，直接运行；禁止先做脚本存在性检测。**即使 `ls` / `os.path.exists` 报不存在、或命令报 `Errno 2`，也不要当成脚本缺失**——先确认命令是不是以 `python3` 开头的单条命令（见 §4 那条红线），`cd`/`mkdir`/`ls` 打头或探测类命令在部分环境读不到技能目录。改成单条 `python3` 重试一次，不要 `find` 满盘搜索（既无效又容易触发命令超时）；**已是单条 `python3` 仍报 `Errno 2` 的，是技能包换版瞬态，等约 10 秒原样重试（见 §4 红线区对应条）**。
   - 脚本按色相重算每个颜色，**保持原色的亮度**（对比度因此原样保留）与颜色之间的色相距离（多色套的几张卡照样区分得开）。
   - `--sat`：饱和度倍数，低于 1 更沉稳，高于 1 更鲜亮；`--spread`：0～1，越小几种彩色越收拢到同一色系。
   - 脚本换完会把本套每一页的「文字 / 所在表面」全部验一遍，通过才写出 `colors.json`；报 FAIL 就换个色相或降饱和再跑，**不要手改它算出来的色值**。
   - **距离闸**：`--hue` 与本套默认主色相的角距小于 `--min-gap`（默认 60°）时，脚本不写 `colors.json`，直接判「用默认配色」并打印两个色相与角距。这时就**走「不改」那一支**：`init` 不带 `--map`，DESIGN.md 记一句「色彩意图 X，主色相 N°，与本套默认 M° 相差 K°，判定吻合，用默认配色」。全池 9 套里 5 套默认是蓝/靛（cartesian、editorial-forest、emerald-editorial、signal 216 上下，cobalt-grid 236），所以蓝色主题配这些套命中闸是常态，不是出错。
   - 命中闸时**不许为了绕开它去换一个并不贴合主题的色相**，也不许手写映射表。要么用默认，要么这份 PPT 真的需要另一个颜色——那就挑一个离默认主色相至少 60° 的色相。
   - 用户点名了颜色（如「用我们的品牌蓝 #1E62D0」）：取该色的色相作 `--hue`；若该色相落在闸内，加 `--force` 照做（用户点名优先于闸）。点名要默认配色时才跳过本步。
3. 深浅方案由套决定，不靠换色翻转：要深底就选默认深底的套（文献综述默认深底、经营分析有暗页外壳），不要指望把浅底套整体反色——`--invert` 多数套会因为保不住对比度被脚本拒掉。
4. 换色随 §4 第 1 步的 `init --map colors.json` 一起完成，不单独跑 `recolor`。色彩意图、色相、`palette` 的参数写进 DESIGN.md。
5. 预设 §6 / §7 里「只用某色」「禁止某色相」的话只约束默认配色。

## 4. 逐页生成（Step7）

页面语言没有母版，外壳靠脚本拼装，不手写。

> **脚本跑不了时的兜底（仍然走模板）**：`init` / `buildall` 无法执行时，用读写文件的工具把所选套的 `shell/content.jsx` 逐字复制成 `00_shell.jsx`，把 `slides/*.slide` 复制成 `ref_*`，每页照外壳**逐字**复制一份、只替换 `〔…〕` 占位和 B 区内容，配色用默认。外壳的任何数值、层级、页眉页脚都不许改。**任何情况下都不允许绕开模板自由发挥版式**——模板是这条链路唯一保证不溢出、不抖动的东西。

**页面文件都在同一个工作目录里，脚本靠它定位产物。**

工作目录**建在会话可写的输出目录下**（如会话输出目录下的 `<项目名>/`），不要建在技能目录里，也不要往运行环境的其他位置试探——**建目录报 `PermissionError` / `Errno 13` 说明选错了位置，不是环境故障**，换到会话输出目录下重建即可，不要逐个盘去探路径。

路径风格二选一，不要混：

- **手写命令时（默认）**：先让当前目录就是工作目录，然后一律用裸文件名——`init` 复制出来的文件和自己写的 `NN_body.jsx` / `NN_vars.json` / `colors.json` / `images.json`，读和写都不加目录前缀（`00_shell.jsx`、`ref_02_cards.slide`），命令也不加 `--out` / `--dir`。少写路径就少一处写错的机会。
- **由程序拼命令时**：显式传 `--out <工作目录>` / `--dir <工作目录>`，用绝对路径，不要依赖当前目录。

这两个参数默认值都是当前目录，所以**当前目录不对又没显式传值，页面就会落到别处**；`buildall` 遇到目录里没有页面会直接报错退出，不会误报 `ALL OK`。

脚本路径始终写全并整段加双引号：`python3 "{baseDir}/scripts/build_page.py" …`（安装路径由运行环境决定，可能含空格或非 ASCII 字符，漏引号会在空格处被拆成两个参数）。

🔴 **命令必须以 `python3` 开头，整条命令里只有这一条 `python3`，前后什么都不加。** 不要 `cd …&&`、不要 `mkdir …&&`、不要 `| head` / `| tail`、不要 `;` 串第二条命令、不要写成 `VAR=…; python3 …`、不要 `python3 -c` 或 `subprocess` 再包一层。工作目录用 `--out` / `--dir` 指定（见上），目录不存在时脚本会自己建，不需要先 `mkdir`。

这不是风格要求，两条都实测过：

- **首词不是 `python3`，脚本就读不到。** 同一条命令、同一个脚本路径，写成 `cd <工作目录> && python3 "<脚本>" palette …` 报 `can't open file …: [Errno 2]`，直接写 `python3 "<脚本>" palette …` 则正常执行。`mkdir`、`ls`、`for`、变量赋值开头一样失败。**报 `Errno 2` 不代表脚本不存在**，先把命令改成单条 `python3` 再判断。
- **管道会把退出码换成 `head` 的 0。** `buildall` 机检失败明明返回 1，接上 `| head -40` 就变成 0，「`ALL OK` 才提交」这道闸门直接失效，溢出和低对比度全部漏过去。
- **单条 `python3` 也报 `Errno 2`，是技能包换版的瞬态窗口**（技能目录在换版的几秒到一两分钟内读不到，与命令形态无关）：**等约 10 秒原样重试**，可重复 2～3 次；持续超过 1 分钟仍失败才算真缺失，把报错原文发给用户。

判断成败只看这一条命令自己的退出码和它打印的完整输出。

**全程只用 `palette`（§3）、`init`、`buildall` 这三条固定命令，不对技能目录跑 `cp`**（每条新命令都可能触发权限确认）；用户上传了自己的 PPT 模板时这三条换成 `template` / `template --docid` / `buildall`，见 [../create-from-template.md](../create-from-template.md)：

1. 执行一次（程序拼命令时加 `--out <工作目录>`）：

   ```bash
   python3 "{baseDir}/scripts/build_page.py" init --set <slug> --map colors.json
   ```

   - `{baseDir}` 表示当前 Skill 所在目录（`wecomcli-pptx`）。执行时必须替换为实际绝对路径。
   - 脚本已经存在，直接运行；禁止先做脚本存在性检测。**即使 `ls` / `os.path.exists` 报不存在、或命令报 `Errno 2`，也不要当成脚本缺失**——先确认命令是不是以 `python3` 开头的单条命令（见 §4 那条红线），`cd`/`mkdir`/`ls` 打头或探测类命令在部分环境读不到技能目录。改成单条 `python3` 重试一次，不要 `find` 满盘搜索（既无效又容易触发命令超时）；**已是单条 `python3` 仍报 `Errno 2` 的，是技能包换版瞬态，等约 10 秒原样重试（见 §4 红线区对应条）**。

   把该套外壳（`00_shell.jsx`，带第二外壳的套另有 `00_shell_dark.jsx` / `00_shell_light.jsx`）、范例页（`ref_*.slide`）和预设一次性复制进来，并按 `colors.json` 换好色（用默认配色时去掉 `--map`）。封面、章节页等外壳取预设 §4 的代码块自己存文件。
2. **每页先挑范例骨架**：打开工作目录里的 `ref_*.slide`，选骨架最接近本页内容的一张，照它的结构改——分栏、卡片形状与间距、字号层级、序号与标志性处理都保留，只换文字和数据。跳过这一步，出来的页面就只剩页眉页脚像模板，B 区跟模板无关，等于白选了套。
3. 每张内容页只写两个文件：`NN_body.jsx`（B 内容区内部，不含 Slide / 页眉 / 页脚；用暗页外壳时命名 `NN_body_dark.jsx`，浅页 `NN_body_light.jsx`）和 `NN_vars.json`（每个 `〔…〕` 占位的取值，可含 `<br />` / `<span>`，留空填 `""`）。封面等非外壳页直接写成 `NN_<名称>.jsx`。
   - **两个文件必须成对，且 `buildall` 只靠 `NN_body*.jsx` 认页**：只写了 `NN_vars.json` 而没写 body，这一页对它是不存在的，不会拼也不会报这一页的问题。body 的后缀决定用哪个外壳（`NN_body_dark.jsx` → `00_shell_dark.jsx`），无后缀回落 `00_shell.jsx`。
   - **`vars` 的 key 来自外壳而不是本页内容**：页眉、页码、页脚、引导问题这些都写在外壳里，所以每页都得自己填一份，`〔…〕` 少一个就拒绝拼页。key 要与外壳里的占位逐字一致，现取一遍最稳（对该页要用的外壳搜 `〔…〕`）；不确定时先跑一次 `buildall`，报错会把该外壳需要的完整 key 列表直接打出来，照抄补齐即可。
4. 写完一批（或全部）页后执行（程序拼命令时加 `--dir <工作目录>`）：

   ```bash
   python3 "{baseDir}/scripts/build_page.py" buildall
   ```

   - `{baseDir}` 表示当前 Skill 所在目录（`wecomcli-pptx`）。执行时必须替换为实际绝对路径。
   - 脚本已经存在，直接运行；禁止先做脚本存在性检测。**即使 `ls` / `os.path.exists` 报不存在、或命令报 `Errno 2`，也不要当成脚本缺失**——先确认命令是不是以 `python3` 开头的单条命令（见 §4 那条红线），`cd`/`mkdir`/`ls` 打头或探测类命令在部分环境读不到技能目录。改成单条 `python3` 重试一次，不要 `find` 满盘搜索（既无效又容易触发命令超时）；**已是单条 `python3` 仍报 `Errno 2` 的，是技能包换版瞬态，等约 10 秒原样重试（见 §4 红线区对应条）**。
   - 🚨 **禁止自写脚本替代 `buildall` 拼装**——自写拼装丢掉 missing-values / `fit` / 对比度全部机检，占位符未命中会静默残留进交付物（实测发生过）。`buildall` 跑不起来就按上面两条跑通它；跑不通停下把报错原文发给用户，不允许绕过。

   一次性把所有 `NN_body*.jsx` 拼成 `NN_page.jsx`，并对全部页面跑**文字装箱**与对比度检查，有 `images.json` 时同时核对图片比例；输出 `ALL OK` 才提交，否则按提示改完再跑一次。报 `OVER` 就是有文字或区块超出了容器，按第 6 条处理。提交用的是 `NN_page.jsx` 和封面等 `NN_<名称>.jsx`。
5. B 区放不下就删内容或拆页，不改外壳任何数值。「与上一页版式不重复」只指 B 区内部。
6. 文字装得下由 `buildall` 机检（`fit` 子命令）：它按字号、行高、字距和实际列宽算出每段文字要占几行，再逐层核对每个定高 Box 直到 720 的 Slide，装不下就报 `OVER … line N … over by N px`。**报了 OVER 只能删字、砍掉一个块或拆页**——不许缩字号、不许改外壳数值、不许把容器改高。写之前先自己粗算一遍，别指望机检兜底：文字块高 ≈ 字号 × 行高 × 1.2 × 行数 ≤ 容器高（编译器的行框是声明行高的 1.2 倍，不写行高按 1.2 倍字号算，导出实测）；每行宽 ≈ 汉字数 × 字号（西文大写 0.75、小写与数字 0.55、`Courier New` 一律 0.6）≤ 容器宽。封面看预设「封面标题容量」；标题按语义断行，「最多 N 行」是上限不是要求；文字不得压到页脚、页码、装饰条。**换行只写 `<br />`，不许在字符串里直接回车**：JSX 把回车折成一个空格，编译器按一行量高度、导出时又按两行画，标题就向下溢出被 B 区卡片盖住（`fit` 会报 `raw line break`）。**同样禁止在数据数组里写 `\n` 转义**——`['平台', 'Win / macOS\n移动端不明确', …]` 配 `{d[1]}` 插值时，编译器把 `\n` 画成真换行（两行），而机检只看到插值占位、按一行量高度，于是定高 Box 实际渲染更高、直接压住下一个区块（`height: 180` 的容器实际可能需 226px）。要多行就把值拆成多个 `<Text>`，或在 `<Text>` 里用 `<br />`；`fit` 会报 `a \n escape inside a string literal`。对称地，**`<br />` 只在 JSX 文本位（`<Text>` 的直接孩子）有效**——写进数据数组的字符串（配 `{d[i]}` 插值）会被当纯文本，六个字符原样画上页面（`fit` 会报 `a <br /> tag inside a string literal`）。同理，标题块左侧这种**没有固定宽度的容器**里的文字不得指望自动折行——编译器按一行量它，一行装不下就 `<br />` 断开或给容器定宽（`fit` 报 `container with no fixed width`）。
7. 装饰与文字不重叠：每套预设 §4「装饰与文字不重叠」标了装饰占位区，文字容器的矩形不得与之相交；封面、章节页、结束页只照该套封面范例的对齐方式排。
8. 范例的占位内容全部替换；页面上不得出现 slug、套名、「范例 / 预览」等内部字样；不写注释；不用 emoji。

## 5. 配图

- **没有生图工具**：当前环境不提供 AI 配图，不调用任何生图接口、不用图生图、不反复重试；任何页面都不放 AI 生成的图，图位只给用户材料图（见 `pptx-api.md` §配图接口）。
- 这是既定形态、不是故障：交付时**不提配图**——不说「无法生成配图」，不把它说成服务问题，不建议用户手动加图、不列「可配某某照片」的清单（接口真的报错时按 create-from-scratch Step7 的报错规则如实说明，不在这里编理由）。用户主动问起配图时，如实说明本技能当前只用用户提供的材料图，可以把照片发过来。
- 材料图上页的门槛：只放照片、真实图表、界面截图这类重画不出来的内容，且原图短边 ≥ 图位边长；材料里的表格、流程图、对比图、文字截图一律不贴图，改用原生 `<Table>`、Box 排版或 SVG 重画；重画不了又不清晰的宁可不放。没有合格材料图的页改用本套其他版式，不留空图位。
- 图位全是正方形：企微编译按 1:1 算裁切，非正方形图会被横向压扁。材料图按真实比例居中留边：`<Image>` 宽高 = 图位边长按真实宽高比缩放（`imgfit` 子命令可代算，自己算也行），`<Image>` 不写 `objectFit`。
- Step6 每张图拿到 `url` 后把接口实际返回的宽高记入工作目录的 `images.json`（`{"<url>": [宽, 高]}`），`buildall` 据此核对。
- 图不加描边、相框、包边线、圆角、阴影；图注放图下方一行。

## 6. 机检

`buildall` 已包含全部机检：外壳由脚本拼装（不会漂移）、文字装箱（`fit`）、对比度、图片比例。Step8 只需在全部页面写完后再跑一次 `buildall`，输出 `ALL OK` 即可；若所选套的预设声明了随页码变化的数值，按其算式逐页核对（现池里各套都不画进度条一类控件）。

## 7. 其他硬规则

- 一次只读一套的预设和范例，禁止跨套「综合」；页型与内容结构按 `../content-contract.md`，命中政务闸门时叠加 `../government-contract.md`。
- 字体只用企微文档字体白名单（design-principle.md §5）：中文无衬线 `Microsoft YaHei`、中文衬线 `STSong`、西文 `Arial` / `Times New Roman`、等宽 `Courier New`；含中文的 Text 必须写中文字体。
- 反 AI 味清单 [anti-ai-slop.md](anti-ai-slop.md) 每页过一遍。
- 对用户说话不露内部实现（见 SKILL.md §特有规则）：选了哪套只用中文风格名说，不说 slug、「随机」「预设」「范例」和文件名。
- 色值不得写成六个纯数字的十六进制（如 `#184785`、`#244972`）：企微导出本地 PPTX 时把这类值当成数字，落地成纯红 `FF0000`，含字母的色值全部正常。每个色值至少含一位 A～F；`palette` 自动改写，`buildall`（contrast）拦截并给出最近的合法值。
- 装饰 SVG 不得依赖透明底：每个 `<svg>` 的第一个绘制子元素（`<defs>` 之后）必须是覆盖整个 viewBox 的实底 `<rect x='0' y='0' width='W' height='H' fill='#所在区域底色' />`，整个 SVG 落在一块纯色区里（不跨渐变光晕、不跨色块边界；整页纹理就让 SVG 自带页底色）；svg 的 style 不写 `opacity`（淡色按比例预混进色值），SVG 内不写 `rgba()`（用 hex 加 `fillOpacity` / `strokeOpacity`）。原因：企微导出本地 PPTX 时给每个 SVG 配一张位图兜底，栅格化不保留透明，Keynote / 预览类查看器读的正是这张兜底——不烘底色就是一块白方块。`buildall`（contrast）拦截。
- 本目录只读，生成过程不得修改。

# 基于用户模板生成 PPT

> **用户发来 PPT 模板 = 风格已经给定，版式还得自己设计。**
>
> 模板只提供三样东西：**整页底图 / 底色**、**页眉页脚带里的页面家具**（细条、logo、页码底纹）、**配色与字体**。
> 这三样由 `template` 一条命令提取成每种页型的外壳。页面上的标题、正文、目录项、图表——**全部由你按这套配色和字体自己设计排版**，不照搬模板的任何形状和文字。
>
> 这条路径不用技能自带的范例池（9 套），也不弹风格预览卡；范例池只在用户没有给模板时使用。
>
> **为什么不复刻模板的形状**：试过，不行。模板版心里的色块、异形裁切图、卡片、装饰大字一旦逐个去描，就会出现外接矩形代替弧形、平涂色块代替渐变、照片丢掉圆形轮廓、小图在它依附的色块被丢弃后悬空、以及一页抽出二十个占位让同一句话被填三遍。**模板的识别度在它的底图和配色里，不在那些形状里。**
>
> 「模板不可跳过」的硬约束在这里指**用户模板生成的外壳**：每一页都由这些外壳拼出，不建空白页插文本框、不在本地往用户模板里填页再导入。

## T0 · 先判定这份文件是模板还是材料

| 看什么 | 模板 | 材料 |
|---|---|---|
| 用户怎么说 | 「用这个模板」「照这个风格」「套公司模板」 | 「按这份内容做」「把这个整理成 PPT」 |
| 文字 | 占位句、示例数据（「单击此处添加标题」「XX公司」「12.5 亿」） | 真实业务内容 |
| 页数与结构 | 版式齐全、每页字少 | 内容连贯、字多 |

两者都像 → 当模板用（走本文件），内容另外问用户要。判定结果写进 `STORY.md` 的来源一节。

## T1 · 从用户模板生成外壳（一条命令）

1. 拿本地文件：`wecom-cli media download` 取 `file_path`（见 [create-from-material.md](create-from-material.md) Step0）；只支持 `.pptx`——用户发来 `.ppt` 时告知先另存为 `.pptx` 再发。下载产物是内部临时副本，不外发。
2. 在工作目录里跑（单条 `python3` 开头，规矩同 [templates/README.md](templates/README.md) §4 红线；程序拼命令时加 `--dir <工作目录绝对路径>`）：

   ```bash
   python3 "{baseDir}/scripts/build_page.py" template "<file_path>"
   ```

   `{baseDir}` 为本 Skill 所在目录，执行时换成实际绝对路径；脚本已存在，禁止做存在性检测；只用标准库，不装包。退出码 2 = 不是 pptx 包（多半是 `.ppt` 没转），请用户另存为 `.pptx` 后再发，拿到新文件重跑。

   产物：

   | 文件 | 内容 |
   |---|---|
   | `00_shell_cover.jsx` / `00_shell_toc.jsx` / `00_shell_section.jsx` / `00_shell.jsx`（内容页）/ `00_shell_end.jsx` | 每种页型的外壳，**只有四行**：页面底色、整页底图 `<Image>`、页眉页脚家具 `<Image>`、以及一个包着 `〔B区内容〕` 的版心 `<Box>`。模板缺哪种版式就没有哪个文件 |
   | `tpl_assets/` | 外壳引用的图：`<页型>_bg.jpg/png`（模板原图，未经加工）、`<页型>_art.png`（页眉页脚家具栅格化成的透明图层） |
   | `DESIGN.template.md` | 设计契约：每种页型的底图 / 家具 / **可用版心尺寸**、模板实际用色、字体映射、**模板自己的字号档位表（带模板原文，说明每档原本是干什么的）**、排版规则。它在模板路径上**取代范例套 `DESIGN.preset.md` 的位置**，是 `DESIGN.md` 的主体，整段照搬 |
   | `template_style.json` | 同样的内容，程序读的版本 |

3. 命令会逐页型打印「版心 宽x高 @(x,y)」和底图 / 家具情况。**没有自检、没有占位清单**——外壳里没有需要填的槽，也就没有填错的可能。
4. 若某页型打印了「**在模板里没有底图也没有页眉页脚家具**」，它的外壳就是一张纯底色页。**别让它空着**：按 `DESIGN.template.md` §1 的提示，用主色铺整页或铺一个大色块，再压大号标题 / 章节号，做成和其他页同一套视觉。章节页最常遇到这种情况。

## T2 · 模板内容隔离（硬约束）

模板里的文字、数字、示例图表**全部是占位**，一律不进 `STORY.md`、不进 `RESEARCH.md`、不上页面：

- 「单击此处添加标题」「XX 公司」「2023 年度」「营收 12.5 亿」「WWW.1PPT.COM」「PART ONE」这类，连同装饰性的英文标签和年份，一概不用、也不要在页面上补回来。
- 页面上的内容只来自用户给的材料、用户的话，或你按 [create-from-scratch.md](create-from-scratch.md) 做的调研。
- 用户明确说「模板里的内容也要用」时才例外，且只取非占位页，并在 `STORY.md` 里注明来源是模板。

## T3 · 对齐与设计契约

`DESIGN.md` 的主体就是 `DESIGN.template.md`（整段照搬，别丢版心尺寸那一列）。页数、结构、每页讲什么照 [human-alignment.md](human-alignment.md) 与 [content-contract.md](content-contract.md) 走，和没有模板时一样；差别只在视觉参数来自模板而不是范例池。

## T4 · 建文档后上传模板图（一条命令）

外壳里的 `tpl_assets/...` 是本地路径，直接提交会失败（`buildall` 会拦）。文档建好拿到 `docid` 后跑一次：

```bash
python3 "{baseDir}/scripts/build_page.py" template --docid "<docid>"
```

它把 `tpl_assets/` 下的图逐张上传，把返回的 url 写回外壳，并更新 `images.json`。

- 只需跑一次，之后 `buildall` 和提交都用在线 url。
- 跨会话续做时 url 可能失效：删掉工作目录里的 `tpl_urls.json` 再跑一次 `template --docid`。
- 自己已经上传过 → `template --urls <json>`，格式 `{"tpl_assets/cover_bg.jpg": "<url>"}`。

## T5 · 逐页制作

每页只写一个文件：`NN_body_cover.jsx`（或 `_toc` / `_section` / `_end` / 内容页的 `NN_body.jsx`）。**不需要 `NN_vars.json`**——外壳里没有占位。

页面的全部内容都排在版心盒子里，宽高见 `DESIGN.template.md` §1 最后一列（它已经避开了保留下来的页眉页脚家具）。

**设计规则**（没有骨架可照，所以这几条是硬的）：

- **只用 `DESIGN.template.md` §3 的色值与 §4 的字体**，不加新色相、不加模板里没有的圆角 / 阴影 / 描边。强调方式照模板：主色色块、色条、大号编号。
- **字号从 §4 的档位表里挑，不要自己定。** 那张表是模板自己用的字号，每档都带「模板原文」告诉你它原本是干什么的——原文是 `O1` / `2O2X` 这类编号年份的大字档属于装饰尺度，要用就同样只放编号或数字，别拿它排标题；用了上百处的那档是正文。同一层级全篇一个字号，定了不再逐页微调。
- **每页一个视觉锚点。** 一页上必须有个明显比别的元素大的东西（大号数字 / 大标题 / 整块主视觉），其余元素围着它组织。所有元素大小都差不多 = 流水线页，返工。
- **版心要填满，不是放得下就行。** 行里的块一律用 `flex: 1` 分宽，**不要写死 `width:`**（要不等宽就 `flex: 2` / `flex: 1`）；纵向按版心高度反推每块该多厚，填不到八成就从别的页并一块过来、或者把这页拆掉。不要靠加空话和拉高固定 `height` 来凑。`buildall` 会直接报空旷（`stays empty at the right` / `empty at the bottom`）。
- **卡片内部同样要填满**：内容垂直占到卡高八成以上，卡越高字越多（高 ≥ 380px 的卡正文不少于 100 字）；卡尾的标签条 / 引文条用 `marginTop: auto` 钉到底部，别让它浮在卡中段。同一行几张卡的标题块 / 正文块 / 尾条三段要在各卡之间高度一致。
- 留白围着锚点留（锚点周围留一圈呼吸空间）；每两个元素之间都留一样大的空是稀薄，不是留白。
- 版式按内容选（相邻页不重复、非对称优先，见 [story-principle.md](story-principle.md) 版式速查）；10 页以上至少 2–3 页视觉重量更高的页，不要每页一个样子。
- 数据用原生 `<Chart>` / `<Table>`，系列颜色按 §3 彩色顺序；表头用主色底白字。
- 反 AI 味清单 [templates/anti-ai-slop.md](templates/anti-ai-slop.md) 照过；不用 emoji；不放模板以外的装饰图。
- **外壳里已有的东西不要在版心里重做一遍**（底图、页脚条、logo 都在外壳上了）。
- **模板主色配白字过不了对比度检查时**（例如 `#5B9BD5` 上白字只有 2.96，门槛 3.0）：不要凭空造模板里没有的颜色来回试。按顺序挑第一个可行的——① 换用 §3 里已有的更深色值；② 该色块上的文字改深色（深字配浅块）；③ 仍不够就把主色压暗到刚好过线，并在交付时说明。一次定下来，不要逐页微调。

写完一批跑 `buildall`（文字装箱、空旷、对比度、图片比例全在里面），`ALL OK` 才提交。提交、重做、页序规则与 create-from-scratch Step7 / Step8 完全相同。几条已经踩过的命令事实，照抄即可，不要另猜写法：

- `buildall` **只有 `--dir` 一个参数**，没有 `--docid`。
- 提交用 `wecom-cli slide pages addjsx`，payload **直接传 JSON 字符串**；写成 `--json @文件名` 会以 `404 server inner http request failed` 失败——那是用法错，不是服务端抖动，换直传即可，不要重试。
- 核对页数 / 页序用 `wecom-cli slide get`（返回 `slide_count` 与有序 `slide_ids`）。**没有 `slide pages list` 这个命令。**

外壳是生成的，**不手改外壳任何数值**；要调版心里的东西就改 `NN_body*.jsx`。

## T6 · 交付说明

交付时加一句（不出现任何内部字样）：「按你给的模板做的：底图、配色和字体都沿用模板，版式按内容重新设计；模板里的示例内容没有使用。」再按实际情况补：

- `DESIGN.template.md` §6 非空 → 逐条说明哪些没能带过来（如「模板里的 WMF 插图没能带过来」）。§7 是内部记录，不写进交付语。
- 模板缺某种版式 → 「模板里没有章节页版式，章节页按模板配色新做了一套」。
- 为过对比度调过颜色 → 「个别色块为保证可读做了加深」。

**不要声称逐像素复刻模板**：模板版心里的装饰是按设计舍弃的，这是方案不是缺陷，不必在交付语里逐条列举。

## 自检（交付前逐条过）

- [ ] 跑过 `template <模板>`，每种页型都有外壳
- [ ] 没读范例池、没跑 `palette` / `init`、没弹风格预览卡
- [ ] 打印了「没有底图也没有家具」的页型，已按主色自己做出视觉，不是一张空白页
- [ ] 每一页都出自 `template` 生成的外壳；外壳没被手改
- [ ] 所有内容都在版心盒子里，且填到八成以上：行里的块用 `flex: 1` 而不是写死 `width:`，`buildall` 没有 `stays empty` / `empty at the bottom`
- [ ] 全篇只用了 `DESIGN.template.md` §3 的色值和 §4 的字体；**字号取自 §4 的档位表**，没有自造中间值，同一层级全篇一个字号
- [ ] 每页都有一个明显的视觉锚点；没有「所有元素一样大」的流水线页
- [ ] 卡片内容占到卡高八成以上，卡尾元素用 `marginTop: auto` 钉底；同一行各卡的分段高度一致
- [ ] 页面上没有任何一句来自用户模板的文字或数字
- [ ] `template --docid` 跑过，页面里没有残留 `tpl_assets/` 本地路径（`buildall` 会拦）
- [ ] 交付语里有「沿用了什么、重新设计了什么」那一句

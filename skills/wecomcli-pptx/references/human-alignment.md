# 人机对齐与需求确认

## 1. 总原则

- 🔴 **提问与预览卡永远不是启动前置门（最高优先级，压过本文件其余所有条款）**：卡片发出后**拿不到回应一律继续做完并交付**——用户没点、审批超时被系统取消、组件不可用、对话被切走，都按「无回应」处理，走下方的**无回应兜底**，用默认值把 PPT 做完。**禁止**因为没等到选择就中止任务、禁止只回一句「因为没确认所以没做」、禁止一个文件都不产出。用户不点，多半是觉得怎样都行，不是要你停下来等。
- **只问缺失的**：先分析用户输入中已明确哪些信息，只对无法确定的关键信息提问。
- **文字提问 ≤ 3**：一轮问完。缺失项 > 3 时按优先级取前 3，其余走默认值。
- **风格预览卡默认必弹**：每次从零生成都弹视觉预览卡让用户选（3 张；命中政务闸门时 2 张；不占文字提问名额），只有用户上传了自己的 PPT 模板或明确要求不被打断时才跳过（详见 §2.3）。
- **先文字后预览卡**：目标和场景的答案会影响预览卡的推荐方向，所以先收集文字答案。
- **问题与选项实时生成**：禁止固定模板，必须结合用户的具体主题生成问题和选项。
- **禁止暴露推理过程**：维度分析、跳过判断、硬约束引用等均为内部逻辑，禁止向用户展示。用户只应看到提问卡片或预览卡，不应看到"已明确 ✓"、"可推断"等分析输出。

## 2. 生成前对齐

### 2.1 需要关注的关键信息（按优先级排列）

| 优先级 | 信息 | 它决定了什么 | 什么时候不用问 | 默认值 |
|---|---|---|---|---|
| P0 | 主题 | PPT 讲什么 | 用户已明确 | —（必须明确） |
| P1 | 核心目标 | 观众听完该做什么/信什么 | 可从主题+场景推断（如路演=说服投资） | 内部推理 |
| P2 | 场景+密度 | 每页放多少信息、叙事详略 | 用户提了场景词（路演/汇报/培训/存档等） | 会议汇报（中密度） |
| P3 | 受众 | 专业深度、措辞口径 | 场景已隐含受众（如路演→投资人） | 内部推理 |
| P4 | 素材忠实度 | 能否改写上传材料的内容 | **用户没有上传材料时直接跳过**；只上传了模板（只取样式）也跳过——模板里的文字不是材料 | 有材料→适度提炼；无→AI 自由发挥 |

> 🚨 **交付形态不在提问范围内**——本技能只交付在线文档链接，**禁止做成提问选项**。

### 2.2 动态提问流程

**第一步：判断哪些信息还缺**

对上表 P0–P4 逐项判断：用户输入中已经明确了？还是可以从上下文推断出来？还是完全不确定？
- 已明确 / 可推断 → 直接采用，不问
- 无法确定 → 加入本轮提问

**第二步：一轮问完**

将需要提问的信息按优先级排列，取前 ≤ 3 个，用 ask 组件一次性发出：

| 信息 | header | 选项方向（实时生成，以下仅为参考） |
|---|---|---|
| P0 主题 | 「主题」 | AI 根据上下文生成候选方向 |
| P1 目标 | 「目标」 | 说服决策 / 传递知识 / 展示成果 / 激发兴趣 等 |
| P2 场景 | 「场景」 | 现场演讲(低密度) / 会议汇报(中密度) / 培训分享(中高密度) / 阅读存档(高密度) |
| P3 受众 | 「受众」 | 领域专家 / 管理层 / 普通同事 / 完全新手 等 |
| P4 忠实度 | 「忠实度」 | 忠于原文 / 适度提炼 / AI 大幅重构 |

**ask 规范**：每问 2-4 选项 `{label, description}`；不预填；不加兜底项（ask 自带 Other 输入框）；多选场景用 `multiSelect: true`。

**不准问的**：**交付形态不问用户**——本技能只交付在线文档链接，把它做成选项既暴露内部实现，又平白多一道卡。同理不问：用不用配图（当前环境没有生图工具）、用哪套模板（预览卡已经在问）、页数上限（超过约 15 页才确认）。

**第三步：无回应就走默认，不要停**

文字提问发出后没拿到回答（用户没点 / 审批超时 / 组件不可用）→ **P1–P4 全部取上表「默认值」列**，P0 主题用用户原话里的题目，直接进 Step3，**不重发、不追问、不中止**。交付时用一句话带过：「按会议汇报的常规密度做的，想换方向告诉我」。

### 2.3 风格预览卡

文字问题收集完毕后，评估是否需要弹出风格预览卡让用户选择视觉方向。

**触发策略（默认必弹）**：每次从零生成都弹卡——3 张，取 Step4 在扁平池上打分的前 3 套；命中政务闸门时只出 2 张（政务工作 / 表彰庆典）。只有两种情况跳过：用户上传了自己的 PPT 模板（风格就是模板：按 [create-from-template.md](create-from-template.md) 从模板生成外壳，**不选范例套、不推配色**）；用户在本次对话里明确说了「不用问 / 直接做 / 别打断」这类话（按 templates/README.md §2 的规则选一套，交付时告知可换）。文字提问被跳过、或信息都能推断而没有发文字提问，都**不算**跳过预览卡的理由——预览卡照样弹。命中政务闸门、用户描述了风格偏好、主题很典型都不算跳过条件——偏好做成 A 卡标「推荐」，其余照常给出。`show_widget` 不可用时退化为纯文字选项，仍然要问。

**无回应兜底（硬规则）**：预览卡发出后没拿到选择——用户没点、**审批超时被系统取消**、`show_widget` 或 `AskUserQuestion` 调用失败——**一律按「跳过」处理并继续生成**：版式取 Step4 打分的第 1 名（并列就在并列的里随机），配色照常按 templates/README.md §3 判定（**不许因为没人回应就直接退回默认**；但 §3 的距离闸判出「与本套默认吻合」时用默认是合法结论），直接进 Step3，把 PPT 做完交付。交付时一句话说明并给出换的路径：「版式和配色是我按主题定的，想换风格说一声，我直接换一版」。

**不准做的**：不重发第二张卡、不在对话里追问「你还没选」、不把「等用户确认」写进 TODO、**不因此中止任务或交付空结果**。卡片的作用是减少返工，不是拦住生成——没人点就等于「你看着办」。

**每张卡的结构**（从上到下依次排列）：
1. 顶部：编号 + 套名（如「A · 项目提案」），推荐卡额外标注「推荐」
2. 色板条：5 个色块横排（主色最宽）+ 每色下方标注 HEX 码
3. 封面缩略图（16:9）：用用户实际主题文字渲染，体现该方案配色和排版气质
   - 文字层级：主标大 + 副标小 + 时间/地点辅助信息
   - 视觉张力：通过色块分割、留白节奏、文字层级对比来表达方案气质
   - 允许：1-2 个简洁几何色块辅助构图（侧边色带、底部色条）
   - 禁止：堆砌 3+ 装饰几何形状；纯色矩形+单行文字的平铺式占位
4. 底部：2-3 个气质标签（每标签 ≤ 4 字，如"商务""极简""科技感"），每个标签画成圆角胶囊（rx=高度/2 的填充或描边圆角矩形 + 居中文字），禁止用纯文本如"pill: xxx"代替

**布局参考骨架**（区域顺序和占比固定，内部内容由 AI 自由填充）：

```
┌────────────────────────── 单卡 ──────────────────────────┐
│ [顶部栏 ~8%]  A · 项目提案            「推荐」        │
├──────────────────────────────────────────────────────────┤
│ [色板条 ~6%]  ████████████ ██████ ██████ ██████ ██████   │
│               #主色        #辅1   #辅2   #辅3   #强调    │
├──────────────────────────────────────────────────────────┤
│ [封面缩略图 ~74%]                                        │
│  版式取所用范例套的封面骨架                                │
│  约束：必须含主标+副标+辅助信息，体现配色与排版气质        │
├──────────────────────────────────────────────────────────┤
│ [标签栏 ~8%]  [商务] [极简] [清新]                        │
└──────────────────────────────────────────────────────────┘
单卡宽高比约 3:4，根据渲染容器自适应缩放。风格名、色板条、标签栏三者共享左对齐线。

横排网格（3 张；命中政务闸门时 2 张）：
┌─────────┐  ┌─────────┐  ┌─────────┐
│  卡 A   │  │  卡 B   │  │  卡 C   │
└─────────┘  └─────────┘  └─────────┘
```

**骨架使用原则**：
- 4 个区域的上下顺序和占比比例保持固定 → 保证卡片结构一致
- 封面缩略图区域占绝对大头 → 视觉焦点明确
- 缩略图内部的版式、色块分割、留白方式以该卡所用范例套的 `slides/01_cover.slide` 骨架为准，不另行发明
- 顶部/色板/标签三个区域格式简单，严格按结构渲染，不做创意变形

**各卡如何拉开差异**：色板不同 · 密度/气质不同 · 封面版式不同。缩小看也能一眼区分。

**卡片构成、配色推导与换色、跳过时怎么选套**：见 [templates/README.md](templates/README.md) §2、§3。要点：每张卡 = 池里一种真实版式 + 一套按主题推导的配色（默认配色用在三种情况：用户点名、推导过不了对比度、§3 的距离闸判定主题色相与本套默认吻合）；3 张卡就是 Step4 在扁平池上打分的前 3 套，命中政务闸门时为政务两套；各卡颜色互不相同；换色按角色表写映射表、过对比度门槛，换色本身随 Step7 的 `init --map` 一起完成。

**卡片的渲染**：色板条取该卡实际使用的配色（默认或推导）；封面缩略图一律以该卡所用范例套 `slides/01_cover.slide` 的版式骨架为准，换上本次 query 的真实主标 / 副标 / 时间位后渲染，禁止直接展示范例自带的占位文字；风格名一律用 `DESIGN.preset.md` 的 `name`，不加括号、不加任何后缀。只读候选卡所用套的索引条目与封面页，不读其他套的任何文件。

**渲染与选择**：用 `show_widget` 内联横排渲染预览卡，随后弹出 `AskUserQuestion` 让用户点选（选项数与卡数一致）。若环境无 `show_widget`，直接用纯文字选项承接。具体时序见下方执行硬约束。

**选定后**：卡片携带的参数（色板、字体、密度基线、版式气质）在后续设计阶段直接生效。
- 选中任何一张卡 → 该卡的版式套即「选定的范例套」，该卡的配色即本项目色板；配色不是默认时，在 DESIGN.md 记下映射表，Step7 的 `init --map colors.json` 会据此换色。页型与内容结构仍按 [content-contract.md](content-contract.md)，命中政务闸门时叠加 [government-contract.md](government-contract.md)。


**执行硬约束（触发预览卡时，违反任一即返工）**：
- 色源禁用通用色板库（visualizer read_me 的 9 色 ramp / Material UI 等）；每张卡的色板都用 README §3 的 `palette --set … --hue …` 现场生成（各卡色相至少差 60°），只有用户点名默认配色或品牌色时才另作处理；不手编色值
- 每张卡各自对应池里的一套真实版式；不允许出现没有版式套的卡，不允许两张卡版式相同，不允许所有卡同一色系；3 套的 tone 与 density 不得全同（Step4 打分的差异项）
- 封面缩略图必须用本次 query 的真实主题文字（主标 + 副标 + Logo/时间位）渲染，禁止色块占位
- 各卡封面版式结构性不同（留白位置、文字对齐方向、图文比例至少一项显著不同，如左大图骑线 / 居中巨字 / 非对称双栏 / 上图下卡等），不允许只换颜色
- 执行顺序锁定：先定各卡的基底套 + 各套色板 → 再 show_widget 渲染 → 再弹 AskUserQuestion
- **渲染或弹卡失败、以及弹出后无回应，都不算返工项**：按上方「无回应兜底」继续生成，不要为了补一张卡而停住整条链路

## 3. 生成后追问

PPT 交付后，仅在用户给出模糊反馈时触发追问。用户无反馈或说"就这样"→ 不追问，不主动询问。

| 用户反馈 | 追问方向 | 改动范围 |
|---|---|---|
| "风格不对 / 太素" | 重新弹预览卡（排除已选） | 更新色板/字体 → 改受影响页 |
| "太长 / 太满" | 怎么压缩？ | 回 STORY.md 调整 |
| "太空" | 补什么？ | 补内容 |
| "看不懂 / 太深" | 调深度 | 局部改页 |
| "要能讲" | 补什么？ | 追加备注/动画 |

改动原则：局部改页优先；风格改动落 DESIGN.md 后改页；页数改动回 STORY.md 重排骨架。

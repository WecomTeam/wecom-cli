# 企业微信表格样式与配色规范

> 规定企业微信在线表格的结构层级、视觉样式、尺寸策略、执行顺序和验收标准。
>
> 本文只定义目标与执行规则。具体 CLI 参数见 `sheet-style.md`、`sheet-structure-operations.md`、`sheet-table-style.md`。

## 先选择处理路由

### 新建在线表格

按实际内容选择 L1、L2、L4～L6，设置样式、边框与尺寸后回读验收。

### 已有表格美化或追加

优先继承既有结构和样式，只修改任务要求的字段。除非用户明确要求结构调整，否则不新增标题行、不改变合并范围、字段名、Sheet 名、单元格值或公式。

优先级：用户明确要求 > 既有工作簿样式 > 本文默认样式。

## L1 使用规则

L1 为可选层级。只有用户明确要求工作表大标题，或内容结构确实需要独立标题行时才创建；不创建 L1 时直接从 L2 或 L4 开始。

选择创建 L1 时，按以下规则处理：

1. L1 独占第 1 行，标题写入 A1。
2. 先确定实际数据区最后一列，再将 A1 合并至该列，例如 `A1:K1`。
3. 新建表格创建 L1 合并属于初始化结构；已有表格仅在用户明确要求新增 L1 时执行该结构调整。
4. 合并前调用 `wecom-cli sheet merge get` 检查冲突；无冲突后调用 `merge set`；合并后再次调用 `merge get`。
5. 合并回读应包含预期范围。若返回 `merges: []` 或缺少预期范围，说明 L1 未完成，不得将 L1 标记为已验收。
6. 不使用文字自然溢出、空白单元格或视觉留白模拟跨列标题。

## 建立层级范围计划

写入任何样式前，先确定实际数据区末行、末列，并生成以下范围计划：

| 层级 | 含义 | 使用条件 | 目标范围示例 |
|---|---|---|---|
| L1 | 工作表大标题 | 需要独立标题行时使用 | `A1:K1` |
| L2 | 表头 | 存在字段列名、跨列分组或分区标题时使用 | `A1:K1`、`A2:K2` |
| L4 | 数据正文 | 存在明细数据时使用 | `A2:K20` 或 `A3:K20` |
| L5 | 表外备注、注释或异常提示 | 存在对应内容时使用 | `A21:K21` |
| L6 | 小计、合计、总计 | 存在汇总内容时使用 | `A22:K22` |

识别规则：

- 存在 L1 时，L1 固定为第 1 行，其他层级从第 2 行或更后位置开始；不存在 L1 时，L2 或 L4 可以从第 1 行开始。
- 字段列名、跨列分组和分区标题统一归为 L2；L2 不要求先存在 L1。
- 禁止把第一条正文数据误判为 L2。
- 不存在的可选层级记录为“无”，不得虚构内容。
- 空白分隔行不属于任何层级，不套用主体样式，也不单独设置边框；位于 L1～L6 之间时被整体外边框包含。

## 层级样式矩阵

| 层级 | 行高 | 字号/字重 | 背景色 | 文字色 |
|---|---:|---|---|---|
| L1 | 80px | 18pt，加粗 | 主题主色 | `#FFFFFF` |
| L2 | 40px | 10pt，加粗 | 原生表格样式的标题行填充色 | 主题对应的 L2 文字色 |
| L4 | 28px | 10pt，常规 | 原生表格样式的第一、第二条纹填充色 | `#10141A` |
| L5 | 28px | 10pt，常规 | `#F0F1F1` | `#6D7176` |
| L6 | 28px | 10pt，加粗 | `#FFF4D8` | `#10141A` |

默认数字格式规则：

| 数据类型 | Number Format |
|---|---|
| 普通文本、长备注 | 默认 |
| 整数/小数 | `#,##0` / `#,##0.00` |
| 百分比 | `0%` / `0.00%` |
| 人民币 | `¥#,##0.00` |
| 日期/时间 | `yyyy-mm-dd` / `hh:mm:ss` |
| 布尔值、短状态、短枚举 | 默认 |
| 身份证号、手机号、工号、邮编、前导零编号 | `@`，值按字符串写入 |

## 主题与原生表格样式

未指定主题且没有既有样式可继承时，使用绿色。同一工作表只使用一种主主题。

| 主题 | L1 背景 | L2 背景 / `header_fill_color` | L2 文字色 | L4 `band_fill_color` | L4 `second_band_fill_color` |
|---|---|---|---|---|---|
| 绿色 | `#1CAB3E` | `#D2EED8` | `#14672F` | `#FFFFFF` | `#F4FCF6` |
| 蓝色 | `#267EF0` | `#D4E5FC` | `#184785` | `#FFFFFF` | `#E4F9FE` |
| 紫色 | `#546DFF` | `#DDE2FF` | `#392785` | `#FFFFFF` | `#F6F8FF` |

L2/L4 原生表格样式规则：

1. L2/L4 背景和斑马纹使用 `wecom-cli sheet table style add`，禁止用静态填充逐行模拟。
2. 直接传定义的 `header_fill_color`、`band_fill_color` 和 `second_band_fill_color`：标题行使用 L2 背景色，第一条纹使用白色，第二条纹使用当前主题色。
3. 表格样式范围只覆盖连续的 L2/L4，不得包含 L1、L5、L6。
4. 区域首行为 L2 时设置 `header_row:true`；确实没有表头、仅有 L4 时才设为 `false`。
5. 创建后调用 `table style list` 获取并保存 `tab_style_id`，再按下方边框规则调用 `table style update`；最后再次 `list` 验证对象范围和标题行状态。具体参数和命令格式见 `sheet-table-style.md`。
6. `table style add` 不保证 L2 表头文字颜色。创建表格样式后，必须对完整 L2 范围调用 `sheet style set`，设置 10pt、加粗、居中及主题对应的文字色：绿色 `FF14672F`、蓝色 `FF184785`、紫色 `FF392785`。不得设置 `bg_color`，避免覆盖原生表格样式的表头背景。

## 边框

所有边框统一使用 `#85888C`，不随主题变化。只设置以下三类边框：

### L1～L6 整体外边框

对所有实际层级组成的整体范围设置**一个**外边框：

- 范围：从首个实际层级的首行到最后一个实际层级的末行，列从 A 列到实际数据区最后一列，例如 `A1:K22`。
- 调用 `wecom-cli sheet border set`，传 `positions: ["outer"]`、`style: "thin"`、`color: "FF85888C"`。

### L2/L4 隔行线与隔列线

通过 `wecom-cli sheet table style update` 设置：

- `row_band_border_color`：`#85888C`
- `column_band_border_color`：`#85888C`

### L5/L6 内部横线与内部竖线

L5 或 L6 实际存在时，分别对各自范围调用 `wecom-cli sheet border set` 设置内部边框：

- `positions: ["inner_horizontal", "inner_vertical"]`
- `style: "thin"`
- `color: "FF85888C"`

即使某个范围只有一行或一列，也仍同时传入 `inner_horizontal` 和 `inner_vertical`，由平台按实际范围应用可生效的边框方向。不得用静态填充或逐单元格样式模拟 L5/L6 内部边框。

### 执行规则

1. 先完成 `table style update`，再执行 `sheet border set`，确保整体外边框最后写入。
2. 整体外边框只调用一次 `border set`：不按 L1～L6 分层分别加外框，不逐个传 `top` / `bottom` / `left` / `right`。
3. L5/L6 内部边框属于例外：对实际存在的 L5、L6 各自范围调用 `border set`，同时传 `inner_horizontal` 和 `inner_vertical`；不得将这两个位置用于 L1、L2/L4 或空白分隔行。
4. 调用 update 时同时显式传入 `header_row`、`first_column`、`last_column`、`filter_button`、填充色及上述两个边框颜色的最终值，避免省略字段回落为默认值。
5. 除 L2/L4 的原生表格样式边框和 L5/L6 的内部边框外，L1 内部、层级之间及空白分隔行均不额外设置内部线。
6. 更新后调用 `table style list` 验证 `tab_style_id`、范围、标题行状态和三个边框颜色；核对整体外边框及 L5/L6 内部边框各次 `border set` 返回的 `affected_range`、`positions` 与计划一致。写入接口返回成功不等于所有方向的边框均已生效。

## 列宽、行高与换行

### 列宽

- 按标题和实际数据中最宽的内容估算。
- 中文和全角字符每字按 15～18px；英文、数字和半角字符每字按 7～9px。左右 padding 20px。
- 单元格中字符超过20个，列宽直接设置为450px。整体列宽限制为 100～500px。
- 使用一次 `dims resize` 的 `col_widths` 设置所有列宽。
- 存在合并后的 L1 时，L1 不参与单列宽度估算。

### 行高

- 所有实际存在的层级必须显式设置对应基础行高，不得只设置连续正文区域。
- 多个层级或不连续行使用一次 `dims resize` 的 `row_heights` 设置。
- 仅当内容在最终列宽内仍无法完整显示时，才开启自动换行并提高该行行高。
- 调整后必须调用 `sheet info get` 回读实际行高和列宽。

## 整体执行流程

1. **探查**：读取实际数据范围、末列、层级、合并、现有样式、边框、行高列宽和表格样式对象。
2. **计划**：按上方规则确定层级范围、主题、边框和尺寸。
3. **处理 L1（如有）**：按 L1 规则写入、合并并回读。
4. **设置表格样式**：按 L2/L4 规则创建原生表格样式并取得 `tab_style_id`。
5. **设置普通样式**：按样式矩阵设置字体、颜色和数字格式；L2/L4 不写入静态背景。
6. **设置边框**：先调用 `table style update` 将 `outer_border_color`、`row_band_border_color`、`column_band_border_color` 设为 `#85888C`；再对实际存在的 L5、L6 各自范围调用 `sheet border set`（`positions: ["inner_horizontal", "inner_vertical"]`，`color: "FF85888C"`）；最后对 L1～L6 整体范围调用一次 `sheet border set`（`positions: ["outer"]`，`color: "FF85888C"`），确保整体外边框最后写入；不设置其他边框。
7. **设置尺寸**：按列宽、行高和换行规则统一设置。
8. **验收**：执行下方五项断言；失败时补写并重新回读。

## 五项验收断言

1. **L1 结构（仅在使用 L1 时适用）**：标题位于 A1，第 1 行独占，合并范围延伸到实际数据区最后一列；回读不应为 `merges: []`，并应包含完整预期范围。不使用 L1 时，本项不适用且不影响验收。
2. **表格样式范围**：`table style list` 返回的范围与 L2/L4 计划一致，标题行状态正确，不包含其他层级。
3. **尺寸**：`sheet info get` 中所有实际层级行高和列宽符合计划。`row_heights` 为稀疏结果时，缺失行按平台默认高度判断；默认高度不等于目标值即验收失败。
4. **样式与边框**：`cells get include:["style"]` 至少检查每个实际层级一个代表区域，分别验证字体、数字格式和换行；L2 代表单元格，`font_color`、`bold` 和 `font_size` 符合当前主题。`table style list` 返回同一 `tab_style_id`，其范围和标题行状态与计划一致，`row_band_border_color`、`column_band_border_color`、`outer_border_color` 均为 `#85888C`；整体外边框的 `sheet border set` 仅调用一次，`affected_range` 等于 L1～L6 整体范围、`positions` 为外边框四个方向、颜色为 `FF85888C`；实际存在的 L5/L6 还应分别存在内部边框调用，其 `affected_range` 等于对应层级范围、`positions` 同时包含 `inner_horizontal` 和 `inner_vertical`、颜色为 `FF85888C`；除此之外不存在其他边框设置。
5. **数据不变**：重新读取值和公式，确认字段名、Sheet 名、单元格值、公式及业务结构未被样式或边框操作意外改变。

写入接口返回成功只代表请求被接受，不代表验收通过。五项适用断言全部成立后，才可报告“已完成”或“验收通过”。

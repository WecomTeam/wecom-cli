# 读取表格数据

## 前置必做

### 获取工作簿全局结构

读取 `sheet-workbook.md`，通过 `wecom-cli sheet workbook get` 获取全部子表的 `sheet_id`、名称和范围。后续读取优先使用稳定的 `sheet_id`。

- 用户明确指定唯一子表，且全部要求均可由该子表回答时，可只读取该子表；
- 用户只提供工作簿链接、使用“这张表/整个表格/全部数据”等工作簿级表达，或一次要求多个不同指标时，不得默认第一个业务子表就是唯一数据源；
- 无法唯一确定目标子表，且不同选择会改变结果时，先向用户确认；能够通过字段、分类值或记录内容定位时，先读取 `sheet-search-replace.md`，依据 `workbook get` 的子表清单，对每个相关子表分别调用 `wecom-cli sheet cells find`（每次必须传单个 `sheet`）定位，不要先追问。

### 探查候选子表结构

将候选子表的 `sheets[].range` 作为探查上界，按以下规则预读数据：

- **必须读取公式**：结构探查必须使用 `cells get` 并传入 `include:["formula"]`；不得使用与 `include` 互斥的 `csv` 模式探查，否则无法识别公式列；
- 总行数不超过 20 行时，读取全部数据；
- 总行数超过 20 行时，首次至少读取前 20 行；预读范围必须覆盖完整列跨度。例如工作簿返回 `A1:Z301`，首次探查至少为 `A1:Z20`；

根据预读数据判断表头位置和数据展开方向，不要默认第一行就是表头：

- **横向表头**：字段位于前一行或前几行，数据按行向下展开；
- **纵向表头**：字段、指标或分类位于前一列或前几列，数据按列向右展开；
- **交叉表头**：前几行和前几列共同构成表头，数据由行标签与列标签的交点定位；
- **多级表头**：一个字段可能由多行或多列标签共同表达，需要结合上下级标签理解完整含义。

同时区分表格标题、说明、单位、空行空列、父级分组行、汇总行与真正的字段标签和明细记录。结合相邻数据的类型和分布确定表头边界、数据起始位置和记录粒度。

写入任务中，必须根据上述带 `include:["formula"]` 的预读结果识别公式列；仅有单元格值的探查结果不能用于判断。后续新增或补写公式列时，沿用相邻记录的公式结构并调整相对引用，禁止自行计算后写入静态值。公式写入与校验按 `sheet-write-cells.md` 执行。

### 映射字段并确定实际读取范围

根据识别出的表头，将用户提到的字段、时间、人员、分类或指标映射到实际行列，计算最终 A1 `range`：

- 20 行数据不足以判断表头、记录粒度或目标标签时，沿数据展开方向继续扩大探查范围；
- 需要完整统计时，读取范围必须覆盖全部参与计算的记录和字段，不能只读取样本；
- 多轮对话中出现新字段、新维度、新时间范围、新分类或新指标时，重新执行需求覆盖检查。当前子表无法覆盖新增要求时，重新做工作簿级定位，不得机械复用上一轮的 `sheet_id`、缓存文件或读取范围。

## 先判断：局部查询还是完整统计

| 任务类型 | 典型请求 | 完整性要求 | 数据获取方式 |
|---|---|---|---|
| 已知小范围局部查询 | 查看 `B2:D10`、读取已定位记录的相邻列、确认某个单元格值 | 只需覆盖明确 A1 范围 | 可用 `cells get` |
| 结构探查 | 识别表头、字段列、数据展开方向、记录粒度 | 只需样本，不得输出完整统计结论 | 用 `cells get` 小范围采样 |
| 完整统计分析 | 实际多少行/人数/订单数、计数、分组、汇总、去重、排序、TopN、占比、趋势、跨子表比较、完整列表 | 必须覆盖全部参与计算的记录 | 按下方当前环境对应的“完整统计执行流程”处理 |

**硬门禁**：只要结论会因漏掉任意后续记录而变化，就属于完整统计分析。

## 读取单元格数据

### 命令

```bash
wecom-cli sheet cells get --json '<JSON 参数>'
```

### 参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `docid` | string | 是 | 工作簿定位 |
| `sheet` | string | 是 | 子表 ID 或名称；大表和自动化任务优先传子表 ID |
| `range` | string | 否 | 纯 A1 区域，如 `A1:B3`；大表读取必须显式传入分批后的范围 |
| `include` | array（string） | 否 | 要额外返回的维度，可任意组合：`formula` / `style` |
| `csv` | bool | 否 | 以 CSV 文本返回；与 `include` 互斥 |

> 当前协议没有定义省略 `range` 时的精确读取边界。需要完整读取子表时，先通过 `sheet-workbook.md` 获取 `sheets[].range`，再自行分批读取，不要直接省略 `range`。

### 返回

| 字段 | 类型 | 必填 | 说明                                              |
|---|---|---|-------------------------------------------------|
| `cells` | array（2D） | 条件 | 2D 单元格数组；未截断时维度与请求区域一致，截断时维度与 `actual_range` 一致 |
| `csv_data` | string | 条件 | CSV 文本（`csv=true` 时返回，此时不返回 `cells`）            |
| `actual_range` | string | 否 | 实际读取的区域 A1                                      |
| `truncated` | bool | 否 | 是否因单次读取上限而截断（单次读区上限 8,000 格）                    |

### `cells` 中的单元格格式

`cells` 是二维数组，每个元素为一个 `Cell` 对象；无内容或未请求的字段会省略。

| 字段 | 类型 | 说明 |
|---|---|---|
| `value` | any | 单元格值，自动推断类型 |
| `formula` | string | 公式，仅在 `include` 包含 `formula` 时返回 |
| `link` / `link_text` | string | 超链接 URL / 展示文本 |
| `image` | string | 图片 URL |
| `rich_string` | array | 富文本分段，按顺序组成单元格内容 |
| `style` | object | 单元格样式，仅在 `include` 包含 `style` 时返回 |

`rich_string` 的每段使用 `value` 表示文本，或使用 `link` + `link_text` 表示链接，可带独立的 `style`。

`style` 可能包含：

- 字体：`font_family`、`font_size`、`bold`、`italic`、`underline`、`strike`、`font_color`
- 单元格：`bg_color`、`horizontal_align`、`vertical_align`、`wrap`
- 数字显示：`number_format`（Excel 格式代码）

颜色使用 8 位 ARGB hex，如 `"FFFF0000"`；返回对象只包含实际存在的样式字段。

### 响应示例（`include: ["formula","style"]`）

```json
{
  "cells": [
    [{"value": "名称", "style": {"bold": true, "bg_color": "FFFFFF00"}}, {"value": "详情"}],
    [{"value": "苹果"}, {"formula": "=SUM(C2:C10)", "value": 1560, "style": {"number_format": "0.00"}}]
  ],
  "actual_range": "A1:B2",
  "truncated": false
}
```

### 使用原则

- 只看值、不需要公式和样式时，使用 `csv` 模式，减少返回体和模型上下文占用。
- 需要保留值类型、公式、链接、图片、富文本或样式时，使用 `cells` 模式。
- `cells get` 的核心用途是局部查询与结构探查；完整统计分析按下方“完整统计执行流程”处理。
- 原始表格数据不得复制进模型上下文或 Python 命令；脚本应直接读取落盘文件。

### 将回包直接落盘

需要把 CLI 回包保存为 JSON 文件时，无需先将完整回包载入模型上下文后再另行写入文件：

```bash
wecom-cli sheet cells get --json '<JSON 参数>' --output '<文件路径>'
```

**落盘格式必须正确理解**：

- `--output` 保存的是 CLI 的 **JSON 响应外壳**，不是可直接交给 pandas 的原始 CSV 文件；
- 请求使用 `"csv":true` 时，真正的表格数据只在 JSON 的 `csv_data` 字段中；必须解析 JSON 后提取 `csv_data`，不能对整个 `.json` 文件执行 `pd.read_csv()`；
- 未使用 `csv` 模式时，真正的表格数据在 `cells` 字段中；`actual_range` 和 `truncated` 是元数据，不是业务数据；
- 每个落盘响应都必须先检查 `truncated`。若为 `true`，该文件只含被截断的数据，禁止用于完整统计；
- 分块读取时，每批单独落盘，并由脚本从各 JSON 文件中提取 `csv_data` 或 `cells` 后按范围顺序合并。

## 数据统计分析执行流程

1. 基于 `sheets[].range` 预先生成覆盖全部目标行列的分块读取计划，每批不超过 8,000 格；
2. 每批使用 `--output '<批次文件>.json'` 落盘，并逐批校验 `truncated:false` 与 `actual_range`；
3. 由脚本直接读取全部批次 JSON，从 `csv_data` 或 `cells` 提取并按范围合并数据，形成数据最终文件；
4. 编写 Python 脚本对最终数据文件进行统计分析
5. 校验计划范围无缺口、无重复，所有目标子表均已处理后，才能输出统计结论

## 读取与搜索的边界  
  
- `cells get` 用于理解表头、读取已知 A1 区域，以及在已定位单元格后读取其所在行或相邻上下文。它不是按内容查找目标位置的接口。
- 当待查找的目标文本已知，但其所在子表、单元格地址或行号未知时：读取 `sheet-search-replace.md`，使用 `cells find` 定位；每次调用必须传单个 `sheet`。子表未知时，先通过 `workbook get` 获取列表，再逐个搜索相关子表。
- 分析任务中当前子表缺少所需字段、分类值或记录时，分别对其他相关子表调用 `cells find`，再读取命中位置上下文；不要省略 `sheet` 试图做工作簿级搜索，也不要只扩大当前子表的读取范围。
- `cells find` 每个子表的分页结果都必须读取到 `next_cursor` 为空；只读取首页或只搜索部分相关子表，不能用于完整统计或工作簿范围的否定结论。
